# 通道层：现在与以后

## 现在：`web`

内置聊天页（React 前端 `frontend/`，由后端在 `/` 托管构建产物）。既是 MVP 的正式入口，也是本地测试台——不依赖任何第三方平台，
手机浏览器打开、加到主屏就是一个"类 App"。

## 接口本体（与 `types.ts` 保持同步）

```ts
export interface Channel {
  readonly id: string;
  // 收到用户消息：立刻返回，不等处理；附件为 "/media/…" 数组
  receive(text: string, contactId: string, attachments?: string[]): { turnId: string };
  deliver(message: OutgoingMessage): Promise<void>;      // 把话送出去
}
```

Agent、记忆、主动性三层不需要改动。**这就是先把通道抽象出来的全部意义。**

> **诚实说明**：目前真正实现 `Channel` 的只有 `web`。微信（`src/wechat.ts`）与 QQ（`src/qq.ts`）
> 两条通道走的是各自的绑定/收件/投递链路，`getChannel("web")` 与 `wechat.deliverToContact` /
> `qq.deliverToContact` 是有意的直连，不是「插拔即用」——所以不要把这个接口描述成"多通道框架"，
> 它现在只是 web 出站的抽象。接第三条通道时再决定是否让微信/QQ 也套进来。

## 三条路线的实际情况（务必先读再动手）

| 路线 | 合规 | 门槛 | 能否主动发消息 | 结论 |
|---|---|---|---|---|
| **企业微信（自建应用 / 客户联系）** | ✅ 官方 API | 需要主体认证 | ✅ 可以 | **合规首选**，但要认证；适合"决定认真做"之后 |
| **QQ 官方机器人开放平台** | ✅ 官方 | 审核（个人开发者可申请） | ⚠️ 受限（有主动消息额度与限制） | **已接入**（`src/qq.ts`，WebSocket 网关 + 扫码绑定）：想快速触达年轻人可试 |
| **微信公众号（订阅号/服务号）** | ✅ 官方 | 主体 + 认证（¥300/年） | ⚠️ 订阅号几乎不能主动推送；服务号客服消息限 48 小时内 | 会直接削弱"主动关心"，不建议 |
| **个人微信（hook / 协议库）** | ❌ 违反用户协议 | 低 | 能 | **不建议**：封号风险高，且随时可能失效 |

> 一句话：**官方通道能主动发消息的都要资质，不要资质的（个人微信）都有封号风险。**
> 已落地的是微信 iLink（`src/wechat.ts`）与 QQ 官方机器人（`src/qq.ts`）两条，企业微信仍停在"要认证"那一档。

## 接入时要注意的三件事

1. **回调必须秒回**：平台要求几秒内响应，处理慢了会重试，造成重复回复。
   → 正确做法是先查重（平台通常给消息 id）→ 立刻 200 → 后台处理 → 再主动发送。
2. **消息去重是必须的**：平台会重推。用 `kv` 表存已处理的平台消息 id 即可。
3. **主动推送要额度控制**：平台一般限制主动消息条数，且用户反感刷屏。
   `src/proactive.ts` 里已按"每天最多一次 + 免打扰时段"收口，接新通道时沿用这套闸门。
